# Three-page frontend endpoint inventory

All staff API calls use `X-RECOVERFLOW-API-KEY` or a staff Bearer session. The navigation has exactly **Intake**, **Review and Negotiate**, and **Control**. Older functional panels remain inside Review or Control so their workflows stay reachable.

| Page / area | Read endpoints | Staff actions |
| --- | --- | --- |
| Intake upload and tracker | `GET /intake/uploads`, `GET /intake/uploads/{id}`, `GET /intake/uploads/{id}/file` | `POST /intake/uploads` (one file per request; the multi-file drop zone submits each), `POST /intake/uploads/{id}/retry` |
| Review priority queue and case | `GET /cases`, `GET /cases/{id}`, `GET /intake/uploads/{id}` for field confidence and source, `GET /invoices?status=pending_review` | `POST /intake/uploads/{id}/confirm-invoice`, `POST /intake/uploads/{id}/confirm-receipt`, `POST /invoices/{id}/review`, `POST /cases/{id}/replies`, `POST /cases/{id}/resume`, `POST /sync/shopify/cases/{id}/confirm` |
| Review draft and negotiation | `GET /agent/proposals`, `GET /agent/proposals/{id}/versions`, `GET /negotiations/cases/{id}` | `POST /agent/cases/{id}/assess`, `POST /agent/proposals/{id}/edit-draft`, `/approve`, `/reject`, `POST /agent/bulk-approve`; `PUT /negotiations/cases/{id}`; `POST /negotiations/cases/{id}/copilot`, `/manual/send`, `/delegate/step`, `/incoming`, `/pause`, `/take-over`, `/stop`; `POST /negotiations/cases/{id}/turns/{turn}/edit` or `/approve` |
| Control ledger and simulated payments | `GET /reports/summary`, `GET /payments/links`, `GET /reconciliation/pending` | `POST /cases/{id}/entries`, `POST /cases/{id}/entries/{entry}/reverse`, `POST /payments/links`, `/cancel`, `/recover`, `POST /reconciliation/{id}/approve` |
| Control provider and collections | `GET /integrations/status`, `GET /integrations/events`, `GET /messages/inbox`, `GET /dunning/campaigns`, `GET /policies/collection` | `POST /sync/shopify`, `POST /integrations/events/{id}/resolve`, `POST /messages/{id}/triage`, `/reply` (sandbox), `POST /dunning/trigger-stage`, `POST /dunning/campaigns/{id}/approve`, `/refresh`, `/record-contact`; `PUT /policies/collection` |
| Control agent, keys and alerts | `GET /agent/status`, `GET /agent/sandbox-outbox`, `GET /fraud/alerts?status=open`; static `/evaluation.json` and `/evaluation.html` | `PUT /agent/policy`, `PUT /agent/autonomy`, `POST /fraud/{id}/resolve`, `POST /agent/proposals/{id}/internal/case_note` or `/collection_draft` |
| Control advanced legacy tools | `GET /invoices/jobs/{id}` | `POST /imports/receivables/csv`, `POST /invoices/manual`, `POST /invoices/upload`, `POST /invoices/jobs/{id}/retry` |

The Intake page itself has no manual-entry form. Advanced legacy tools appear in Control. Payment events and customer messages in the demo are **SIMULATED**. WhatsApp and email outbound actions write only to sandbox outboxes. [Evaluation](evaluation.md) is generated by `scripts/run_evaluation.py`; the same run generates `frontend/evaluation.json` for the Control summary and `frontend/evaluation.html` for the detailed link.
